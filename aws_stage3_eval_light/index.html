평가 시나리오

2단계에서 완성한 도서 관리 시스템(Next.js 15 + Spring Boot 3.x · Java 21)을 선택한 트랙으로 AWS에 배포합니다.
배포 완료 후 외부 URL에서 메모 CRUD 전체 기능이 정상 동작해야 합니다.

❌
배포 구성(VPC 설정·환경 변수·CI/CD 파일)은 반드시 직접 구현해야 합니다.

평가 진행 순서

  1. 트랙 선택 및 GitHub URL · 배포 URL 제출
  2. 배포 URL 강사 확인 — 브라우저 직접 접속
  3. 3분 라이브 시연 — 목록 조회 → 등록 → 수정 → 삭제
  4. 질문 1~2개 — 선택 트랙 아키텍처 흐름 설명
  5. 루브릭 채점 & 피드백

평가 후 리소스 정리 순서 (비용 절감)

서비스시간당 요금정리 순서

공통 구현 요구사항 (트랙 무관 전원 필수)

항목구현 내용완료 조건
1 VPC 네트워크퍼블릭·프라이빗 서브넷 분리, IGW + NAT GW, SG 체인 구성서브넷 available
2 RDS MySQL 8.0DB 서브넷 그룹, 퍼블릭 액세스 아니요, schema.sql 실행 (3건 확인)RDS available
3 IAM 권한EC2 Role(SSM+S3+CloudWatch), CI/CD IAM User 인라인 정책 최소 권한역할 생성 완료
4 앱 정상 동작배포 URL에서 CRUD 전 동작, /actuator/health → UP, DB 연결 포함브라우저 CRUD 동작

보안 그룹 체인 (트랙 A 필수)

FE-ALB-SG → FE-EC2-SG → BE-ALB-SG → BE-EC2-SG → DB-SG

각 SG는 앞 단계의 SG ID만 소스로 허용합니다. IP(0.0.0.0/0)로 열면 보안 체인이 깨집니다.

GitHub Actions deploy.yml 구조 (4-Job)

name: Full-Stack Deploy
on:
  push: { branches: [ main ] }
jobs:
  build-backend:    # Job 1: ./gradlew test bootJar
  build-frontend:   # Job 2: npm run build (NEXT_PUBLIC_API_URL 주입)
  upload-to-s3:     # Job 3: needs[1,2] → S3 업로드
  deploy-backend:   # Job 4-A: SSM Rolling 배포
  deploy-frontend:  # Job 4-B: SSM Rolling 배포
# Secrets: AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_ACCOUNT_ID / BACKEND_ALB_DNS

buildspec.yml + Procfile
buildspec.yml / Procfile
# buildspec.yml
version: 0.2
phases:
  install:
    runtime-versions:
      java: corretto21
  build:
    commands: [ "cd backend && chmod +x gradlew && ./gradlew test bootJar --no-daemon" ]
  post_build:
    commands: [ "cp backend/build/libs/note-app.jar ." ]
artifacts:
  files: [ note-app.jar, Procfile, .ebextensions/**/* ]

# Procfile (프로젝트 루트)
web: java -Dserver.port=5000 -jar note-app.jar
